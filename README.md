# Fukugan （複眼）

複数の USB ウェブカメラで立体（3D）映像を撮影し、Quest 3 などの VR ヘッドセットで
見られる形で配信するアプリです。

2 台のカメラの映像を左右に並べた side-by-side 映像に合成し、H.264 に符号化して
HLS で配信します。ヘッドセットのブラウザ/プレイヤーでそのアドレスを開けば、
そのまま立体視できます。

設計の考え方は [docs/DESIGN.md](docs/DESIGN.md) にあります。

## 特徴

- **最小構成で完結**: 外部サーバーは不要です。内蔵の HTTP 配信（HLS）だけで
  撮影から視聴まで通ります。外部の MediaMTX への RTSP/SRT push は任意の追加経路です。
- **ハードウェア符号化に自動対応**: 起動時に NVENC を実際に試し（実地プローブ）、
  使えれば使い、使えなければ理由を表示して libx264 に自動で落ちます。
- **カメラ較正**: チェッカーボードによるステレオ較正を持ち、結果を保存して
  再利用できます。手動のオフセット調整だけでも実用になります。
- **3 台以上にも対応**: 主ペアは最も外側の 2 台、中央のカメラは同期基準と
  フォールバックに使う設計です（全台のステレオ化はしません）。
- **仮想カメラ内蔵**: 実カメラがなくても、テストパターンを生成する仮想カメラで
  全経路を試せます。
- **黙って失敗しない**: カメラが開けない、同期がずれる、符号化方式が落ちる——
  すべての失敗と劣化は理由つきで UI と `/api/status` に表示されます。
- **プライバシー**: テレメトリなし。映像が端末の外に出るのは、利用者が
  指定した配信先への push だけです。

## 必要なもの

- Python 3.10+
- OpenCV / NumPy（`pip install -r requirements.txt`）
- FFmpeg（PATH にあること。NVENC を使う場合は NVIDIA ドライバ環境も）

## 使い方

まず仮想カメラで試すのが確実です（実カメラ不要）:

```bash
pip install -r requirements.txt
python -m fukugan --virtual
```

ブラウザで `http://127.0.0.1:8080/` を開くと制御 UI が出ます。
ヘッドセットから見るには、LAN 向けに bind して起動します
（下記の「内蔵 HTTP に認証はありません」を必ず読んでください）:

```bash
python -m fukugan --virtual --host 0.0.0.0
```

ヘッドセットで開く HLS アドレス（`http://<この端末の LAN アドレス>:8080/hls/index.m3u8`）は
起動時のコンソールと制御 UI の両方に表示されます。LAN アドレスを自分で
調べる必要はありません。`127.0.0.1` に bind したままの場合は、ヘッドセットから
届かない旨と `--host 0.0.0.0` の案内が表示されます（設定の `server.host` でも同じです）。

実カメラで使う場合:

```bash
python -m fukugan --config examples/config.example.json
```

設定は JSON です。主な項目:

| 項目 | 意味 |
|---|---|
| `cameras[]` | カメラ一覧。`type` は `device`（実カメラ、`index` で指定）または `virtual` |
| `pair` | ステレオペアの明示指定（空なら自動: 最も外側の 2 台） |
| `output` | 出力サイズ・フレームレート・ビットレート |
| `sync.tolerance_ms` | 同期の許容ずれ（既定 50ms） |
| `encoder.preference` | `auto` / `nvenc` / `x264` |
| `stream.rtsp_url` / `stream.srt_url` | MediaMTX 等への push 先（任意） |
| `stream.hls_dir` | HLS の出力先ディレクトリ |
| `server.host` / `server.port` | 内蔵 HTTP の bind（既定は `127.0.0.1:8080`） |
| `alignment` | 眼ごとの手動オフセット（ピクセル） |
| `calibration_dir` | 較正結果の保存先（下記） |

## 較正

チェッカーボード（既定は内側 9×6 角、1 マス 25mm）を両カメラで同時に写した
画像の組を用意し、次を実行します:

```bash
python -m fukugan calibrate \
  --left left/*.png --right right/*.png --out calibration/
```

再投影誤差と基線長が表示され、結果が `calibration/` に保存されます。
設定の `calibration_dir` にこのディレクトリを指定すると、起動時に
平行化マップが適用されます。較正の質が低い（ステレオ再投影誤差が 1px 超）
場合は、警告を表示したうえで読み込みます。

## 正直な限界

- **実カメラ・実 GPU・実ヘッドセットでの動作は未検証です。**
  開発・検証は仮想カメラとソフトウェア符号化で行いました。
  NVENC の経路は「プローブで実際に符号化できること」をもって使う設計ですが、
  実 GPU 環境での通し確認はまだありません。
- **ソフトウェア同期の精度には限界があります。** USB カメラにハードウェア
  同期はなく、実効精度は数十 ms オーダーです。速い動きでは左右のずれが
  見えることがあります。
- **USB 帯域**: 複数台の高解像度カメラは USB バス帯域を取り合います。
  ハブ経由ではフレームレートが落ちることがあります。帯域の広いポートへの
  分散が有効です。
- **内蔵 HTTP に認証はありません。** 既定では `127.0.0.1` のみに bind します。
  LAN 向けに bind すると、同じネットワークの誰でも映像を見たり
  アプリを操作したりできます。信頼できるネットワークでのみ使ってください。
- HLS の遅延はセグメント長（既定 2 秒）の数倍程度あります。低遅延が必要なら
  MediaMTX 経由の WebRTC 視聴を検討してください。
- 視聴側の立体視はプレイヤーの side-by-side 表示機能に依存します。

## テスト

```bash
pip install pytest
python -m pytest tests/
```

単体テスト（同期・合成・較正の計算・符号化コマンド構築・設定検証）に加え、
仮想カメラで キャプチャ→同期→合成→符号化→HLS→HTTP 取得 までを通し、
配信された映像のフレーム番号が前進することを確認する E2E テストが含まれます。
